# 2026-09-23 — Gallery launches: History in Words on Typortrait.com

3 commits, `20c2312` → `fed7356`, on `claude/pet-engine-v2`. `TYPO_GALLERY_ENABLED=1` on
`typortrait-stg` and `typortrait-prod`; still off on `lovedinwords`, `faithinwords`,
`pawsinwords`. Live at typortrait.com/gallery.

---

## What it is

The Gallery storefront (Stripe checkout, Printful print fulfillment, digital downloads,
per-item SEO product pages) has existed in the codebase for a while but stayed disabled —
built for an unlaunched FaithInWords "Portraits of Christ" pilot, never given real content
for the Typortrait flagship. This checkpoint seeds it with "History in Words": 23
typographic portraits of historical figures (Poe, Lincoln, Twain, Douglass, Tubman,
Anthony, Whitman, Sojourner Truth, T. Roosevelt, Tesla, Grant, B.T. Washington, Sitting
Bull, Geronimo, Barton, Stanton, Darwin, Queen Victoria, John Brown, Barnum, Chief Joseph,
Dickinson, Robert E. Lee), each with a watermarked public preview and a full-resolution
private master for paid delivery, and turns the flag on for Typortrait only.

## What went wrong on the way, worth remembering

None of these were caught by reading the code alone — each surfaced only when actually
testing the live flow, which is the reason to always test the live flow.

- **Shared catalog + shared private-art directory.** `catalog.json` and
  `PRIVATE_DIR/gallery/` hold every brand's items together, not per-brand. Before this
  checkpoint, `typortrait-prod`'s own private directory already held a complete, real
  (non-placeholder) master set for the entire unlaunched FaithInWords pilot — all ~97
  devotional items. The gallery's only brand restriction was a client-side JS allowlist
  in `gallery.html`, filtering the *browsable grid* only. The single-item product page
  and single-item checkout — the exact flow a real buyer uses — had **no server-side
  brand check at all**. Enabling the flag as originally planned would have let anyone
  buy any FaithInWords item through the secular Typortrait storefront at a guessable
  `/gallery/<item_id>` URL. Fixed in `fed7356`: `_brand_collections()` (an existing hook,
  wired into 4 call sites but always returning "allow everything") now does real
  host/`?brand=`-based gating, and `gallery_item_page` + `gallery_checkout` are now wired
  to it, matching the pattern `gallery_bundle_checkout` already used.
- **Hardcoded "FaithInWords" branding in digital delivery.** The outer zip filename, the
  internal per-file names, and the bundled Read Me.txt were all unconditionally labeled
  "FaithInWords" — leftover from when the Gallery had only ever served that pilot. Caught
  on the first real test purchase (Abraham Lincoln, correctly Typortrait-branded through
  checkout, delivered as `FaithInWords-abraham-lincoln.zip`). Fixed in `395fe12`; disk
  caches for both the per-item and per-bundle zips are now keyed by brand label so a
  cached zip built for one brand can never be served stale to another.
- **`typortrait.com` had no nginx route to the app for `/gallery` at all.** The bare
  domain has only ever served the static marketing site
  (`root /var/www/typortrait.com; try_files $uri $uri/ =404;`); every app-served page
  lived at `app.typortrait.com` instead. `/gallery` 404'd from nginx itself, never
  reaching the app, even with the flag on and the code correct. Added `location /gallery`,
  `location /collections`, `location /static/gallery/` proxy blocks to
  `/etc/nginx/sites-available/typortrait.com` (backed up first as
  `typortrait.com.bak-gallery-20260923`), same proxy pattern as `app.typortrait.com`.
- **Static files bypass the Docker image entirely.** `docker-compose.yml` bind-mounts
  `./static:/app/static:ro` — deliberately, so a `git pull` on a tree updates its static
  content live with no rebuild needed. That means a tree's static content depends on
  *that tree's own git checkout*, independent of which image tag is promoted to it.
  `typortrait-prod` had its image correctly rebuilt and promoted to `fed7356`, but its
  working tree was left detached at an old commit — the app code was current, the
  catalog/art on disk were not, so `/gallery` loaded but every item 404'd
  (`gallery_catalog.collection_of("mark-twain")` → `None`) with no error anywhere to
  explain why. Fixed with `git checkout fed7356` on the prod tree. Any future static-only
  change needs this same step remembered per tree, separately from build/promote.

## Closing state

- `typortrait-stg` and `typortrait-prod`: image `typortrait:fed7356`, git tree at
  `fed7356` (detached), `TYPO_GALLERY_ENABLED=1`.
- Verified live on typortrait.com: `/gallery` → 200, only "History in Words" (23 items,
  no devotional collections); `/gallery/jesus-compassionate-savior` → 404 on the default
  brand, 200 under `?brand=faithinwords`; `/gallery/mark-twain` → 200.
- Pricing: kept the shared gallery schedule as-is ($29 digital / $79 framed / $59 canvas /
  $34 poster) — no per-collection price override built. If FaithInWords ever launches
  wanting different physical pricing from History in Words, that's a real schema/code
  change, not configuration.
- Not done: FaithInWords' own `BRANDS` entry in `gallery.html` still has no explicit
  collection allowlist (shows everything in `catalog.json` by design, since the pilot's
  catalog IS the full devotional set). Fine while `TYPO_GALLERY_ENABLED` stays off on
  that tree; if it's ever turned on, re-check nothing from `historyinwords` leaks into it
  the same way this checkpoint closed the reverse leak.
