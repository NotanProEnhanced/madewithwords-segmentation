## What customers see differently

**Groups are sized like single portraits.** Two people in one photograph had type that
changed size between them. The cause was a branch: one subject took a floor off the face
hull, several subjects took an additive ramp from near zero.

    01-hat    df mean 0.948  L=0%   M=0%   F=96%  Mi=4%
    05-couple df mean 0.661  L=15%  M=50%  F=24%  Mi=11%

Same engine, same words. `b8cf474`.

**Laughing eyes are no longer read as shut.** Three people laughing rendered with dark discs
over one subject's eyes. Every face failed the openness gate — `ear` 0.101 to 0.164 against a
threshold of 0.15 — so none got an iris, pupil or catchlight, and the unlit sockets rendered
as bare ground. Nothing drew those discs; they are what is left when nothing draws an eye.
Threshold now 0.09. `f77dcb7`, `b3160db`.

**Every subject's eyes are protected from the shadow cut.** The breathe pass removes 66% of
the ink from deep facial shadow and shields eyes and lips from it — but built that shield
from the primary face only, while applying the cut to all of them. `9ddaa9a`.

**Deep shadow no longer goes to black.** `_ink = _pc/_pl * (3.0 + 250*_tone)` painted letters
at value 3 in shadow. Neither polarity knob touches it. Near-black pixels as a share of the
frame: 13.2% at 3, 7.3% at 40, 1.0% at 80. Now 40. `728d31e`, `086aa37`.

**Type reaches the bottom edge.** The drape samples downward on bright regions, past a text
canvas that was exactly frame-height, where the border returned nothing. Measured at
one-percent resolution on a pale chest: glyph coverage held at 0.25 to 94% of the frame, then
0.152, 0.128, 0.121, 0.120, 0.098. Both engines now draw the canvas taller than the frame.
`8cd29a3`, `5cb372e`, `1a7f1d8`.

**The human brands use the human engine.** LovedInWords, EverLoved, keepsake and FaithInWords
all carried `petEngine:true` and rendered through `pet_proto.py`, the landmark-free engine
built for animals. Every fix above reached app.typortrait.com and none of them reached the
brands that most needed them. `b64af87`.

**Mosaic and Passage render through the Lifelike engine everywhere.** `lifelike_route_on()`
defaulted OFF and only LovedInWords set the flag, so a pasted tribute rendered as a portrait
on one brand and a wall of text on the others. `8d086fc`.

**Studio.** Format is chosen from the words rather than a card. Florals reachable on the
memorial brands and FaithInWords, with a "None" chip. Backdrops visible at all — the group
had never been shown outside the pet flow. One light neutral, labeled Slate. Word size
offers only the two readable sizes. `900ccdf`, `c7fe4af`, `8484bb1`, `cf6f54c`, `e209290`.

**Pet engine.** Background between two adjacent subjects no longer fills as subject — hole
sizes measured (0.059%, 0.242%, 0.533% for real dropouts against 2.781% for the pocket),
threshold in the gap. `55df3f5`.

## Recovering

States (`ops/stg.sh list`) hold commit, `.env` and a tagged image per tree; restore re-tags
rather than rebuilds, so it takes seconds. Tags `v-2026-09-02`, `-02b`, `-02c` name the
day's checkpoints.

    ./ops/stg.sh list
    TREE=/root/typortrait-<name> ./ops/stg.sh restore <state>

States do **not** cover `data/` — the orders database, sources, outputs. That is the backup
job's responsibility.

## Two things that cost the most

**Ask the container, not the file.** `.env` is an input to a container's environment, not the
environment. Compose defaults, literal values and duplicate declarations sit in between. Four
explanations for a dark render were proposed and discarded before anyone ran
`docker exec … printenv`, which would have shown `TYPO_POLARITY=1` immediately.

**A tree can pull from a peer instead of the source.** A five-tree deploy reached four
and skipped staging, with no error. Staging's `origin` was `/root/typortrait-lovedinwords`
— a local path to another tree, not GitHub — so it pulled from a clone that the same loop
had not reached yet and fetched the previous tip. Not intermittent: staging trails
lovedinwords by one deploy, every time, by however far apart the loop visits them.

`tt list` reported all five identical throughout, because it printed the branch name and
all five carried the same name across a three-commit gap. The commit and the remote are
now columns in it. A fleet table that cannot show drift is worse than none: it was
consulted, and it gave the all-clear.

**Test on the configuration that does not compensate.** The style-card change was verified on
`?brand=lovedinwords` — the one brand whose `.env` routes Mosaic through the Lifelike engine
and therefore hides the fault. Two live sites rendered as walls of text. Both of the day's
expensive faults hid behind a setting that made the broken case look fine, and the
configuration you reach for instinctively is usually the one carrying the most local tuning.

# Later the same day — looking at what we actually ship

## The thing that changed everything

**Nobody had ever seen a delivered file.** `/render` clamps output to `PREVIEW_PNG_WIDTH`,
so no tool that talks to it could produce one. Measured, finally:

    typical glyph on screen        4.0px
    typical glyph in the download 11.0px

Composition is faithful — preview against delivered file, ratio **1.000**, so `_ssn` does
normalize supersample exactly as its comment claims. The gap is resolution alone. But 4px is
not a letterform, and every aesthetic judgement this project has made — "27 is unreadable",
"the eyes look wrong", "too dark" — was made on marks a quarter the size the customer gets.

`TYPO_OPS_PREVIEW_PX` (staging only) lifts the cap; `FULL=1 ./ops/render-one.sh` uses it.

**The measuring instrument failed the same way the eye does.** `preview-fidelity.sh` first
reported "COMPOSITION DIFFERS" (ratio 0.687). Connected components are not scale-invariant:
at 900px letters merge into one blob, at 3600px they separate — 1843 blobs against 5460 from
the same artwork. The tell was p75 being *identical* in both columns while the median moved;
a real composition change scales every percentile together. Fixed by measuring both at one
size. The noise floor is now documented rather than tuned away: a 4px median quantizes the
ratio in ~25% steps, so the preview is too coarse to measure its own type — which is exactly
why it is too coarse to judge by eye.

## What the first honest look found

**A LovedInWords portrait shipped with a stadium crowd cut out as part of the subject.** Not
a regression — the preview has it too. `TYPO_MATTE_MODEL=1` is RVM, a *human* matting model:
it answers "which pixels are a person?", and a crowd is people, so it is right. `_clean_mask`
then keeps every blob down to 15% of the largest, written so a second person standing apart
survives; a crowd survives on the same rule. Nothing restricts the result to the people whose
faces were detected, though `analyze.py` has had the face list all along and passed only the
first, to a parameter used solely by the GrabCut fallback.

Measured on the failing photograph: **one blob, 76.7% of the frame, both faces inside it.**
So `TYPO_FACE_ANCHORED_MATTE` — which drops face-less blobs, and works — cannot fix this
photograph. The report says so in words rather than leaving it to be inferred, and that is
why the flag ships off.

Still open. The next question is whether RVM is *less certain* about the distant people
(then `TYPO_MATTE_ALPHA` is the whole fix) or equally certain (then only a geometric rule
anchored on the faces will do, at real risk to hair and shoulders on every other portrait).
`_alpha_sweep` answers it in six lines. First run returned 0.00% at every threshold on an
image the previous run had matted at 76.7% — unexplained, staging only, and the sweep now
prints the alpha's dtype, shape and range so the next run says which of three causes it is.

**A face-anchored region does NOT fix it — measured, then abandoned.** The idea was to keep
only the mask inside a box scaled from each detected face. The grid says no:

    setting        stadium photo      the ten known-good
    above 0.3      5.7% removed       0.5% .. 7.0% removed
    above 0.5      0.1%               0.0%
    above 0.8+     0.0%               0.0%

There is no setting that helps the broken photograph and spares the good ones — at the only
setting that removes anything from the crowd, one of the ten loses *more* than the crowd
photo does. In hindsight the reason is plain: the faces there are large, so a box scaled
from them covers the frame, and the crowd is wrapped around and behind the subjects rather
than sitting neatly above them. There is nothing for a rectangle to cut. The code stays as a
REPORT only, `TYPO_FACE_REGION` off, so the next person can re-measure rather than re-guess.

Coverage is not a detector either. The stadium mask is 76.73% of frame; `01-hat` is 76.03%
and `02-glasses` 72.03%. A broken photograph is indistinguishable from a good one by area,
so these cannot be flagged automatically for the touch-up prompt.

**ISNet separates what RVM fuses — the first thing that moved the number.** Same photograph,
same code, one `.env` line:

    RVM    >0.5 = 76.45%   1 blob    1 holding a face
    ISNet  >0.5 = 70.22%   3 blobs   2 holding a face  -> 2 after _clean_mask, 69.36%

RVM is a *human* matting model, so a crowd is subject and it fuses with the couple into one
76.7% mass. ISNet is a *salient object* model: it returns the two subjects as separate
components (36.6% and 32.8% of frame) and the crowd small enough that `_clean_mask`'s own
size floor drops it. `TYPO_FACE_ANCHORED_MATTE` is a no-op in that state — it finds two
blobs, both with faces, and removes nothing. ISNet alone did it.

Costs, before anyone switches a live tree: renders went 7-8s to 10-11s, ~40% slower on every
preview and swatch; and it changes the matte for EVERY photograph, so `07-dark-on-dark` and
`08-white-hair` — where a person-specific model earns its keep — have to be looked at, not
byte-compared. `compare-testset.sh` reports all ten differing and that means nothing here.

**A run's name does not record what changed.** `render-testset.sh` files under
`<commit><signature>`, and the signature is built only from the script's own knobs. The matte
model, `TYPO_SEG_PAD` and `TYPO_MATTE_ALPHA` all come from `.env`, so an RVM run and an ISNet
run at the same commit get the same directory and the second silently replaces the first --
which is what happened to tonight's RVM baseline. `NAME=` is the workaround; reading the
render-affecting env into the signature is the fix. Same shape as `tt list` printing the
branch but not the commit.

**The test set could not have caught it.** All ten sources are clean studio backdrops; not
one has another person behind the subject. Sources 16 and 17 added to `TESTSET.md` as a
deliberate *pair* — a crowd that is separate (face-anchoring fixes it) and one that touches
the subject (it cannot). A set with only 16 would report a solved problem.

## Quietly wrong, now right

**Backups had been failing for hours, and the cap was not the whole story.** B2 denied every
read at the daily Class B limit — because `backup.sh` ran `prune` *and* `check` on every
hourly pass, 24 full repository metadata reads a day. Both now run only under `--maintain`,
once daily. Two corrections to what was said at the time: a Class B cap does not merely block
restores, it stops backups too (restic reads the config and indexes before writing); and the
hourly cron line was *missing entirely* — the second time in this project's history.

**The backup job answered "I cannot read the repository" with `restic init`.** On the 403 it
tried to initialise over a live repository holding every backup we have. It failed only
because init also needs a read. Now a 403 fails loudly and init runs only when the repository
is genuinely absent.

**`_ensure_clean_png` could serve a truncated PNG.** `path.exists()` goes true when the file
is *created*, not when it is complete, and `write_bytes` is not atomic: under concurrent
reads of an 8MB write, **248 of 264 reads returned an incomplete file**. Latent while only
`/download` composed; routine once the loupe warms the same file. Now serialised per output
path and written via rename.

**"View up close" showed blur and called it detail.** It enlarged a whole-frame 2000px render
to 3× — a 6px glyph magnified — directly beneath a note promising the download is sharper.
Raising the loupe's resolution does not reach legibility either (3000px only gets to 9.2px),
so it now serves a true 1:1 crop of the delivered file, composed by the same call `/download`
uses and cached, warmed when the loupe opens so the wait overlaps with looking.

**Word suggestion was offered where it can never run.** No `OPENAI_API_KEY` on staging or
FaithInWords, so the button said "aren't available right now" — a passing outage, it isn't.
The studio now asks on load and removes the control where it is not configured. The absent
key is a decision, not an oversight: it is the one call that sends customer tribute text off
the machine.

**Spelling.** 558 replacements across 77 files, British to American, verified as exactly that
substitution and nothing else. Quoted Douay-Rheims scripture, published artwork titles, the
word lists rendered *into* existing gallery pieces, and the gallery item id
`christ-saviour-el-greco` were left verbatim — a blanket pass would have rewritten that id
and broken every URL pointing at it.
